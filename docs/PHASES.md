# VELUM — План работ по фазам

> Версия: 1.0
> Согласовано: 13 апреля 2026
> Бизнес-процесс: `docs/BUSINESS_PROCESS.md`

---

## Текущее состояние

Что **уже работает**:
- Трёхслойный pipeline анонимизации (regex → spaCy/GLiNER NER → LLM-верификация)
- Split-screen UI (оригинал слева, анонимизированная версия справа)
- Entity overlay с цветными плашками по типам
- Контроль сущностей: accept/reject/edit каждой, ручное добавление через SelectionToolbar
- EntityNavigator (боковая панель со списком сущностей)
- Экспорт анонимизированного .docx с metadata scrub
- Деанонимизация текста (по mapping table в памяти)
- Dark/light тема, RU/EN локализация

Что **не готово** для Phase 1:
- **Загрузка ответного документа** (.docx от LLM) для деанонимизации — отсутствует
- **Деанонимизация .docx** (не текста, а файла с сохранением форматирования) — отсутствует
- **Экспорт деанонимизированного .docx** — отсутствует
- **Persistence сессий на диск** — mapping table и сессии живут только в RAM, теряются при перезапуске
- **Fuzzy matching плейсхолдеров** при деанонимизации — отсутствует
- **Обнаружение неизвестных плейсхолдеров** в ответе LLM — отсутствует
- **Качество анонимизации** — текущий pipeline использует `ru_core_news_sm` (маленькая модель spaCy), нужно довести до production-grade

---

## Phase 1 — Безупречный round-trip

**Цель:** юрист загружает .docx → анонимизирует → экспортирует → работает с LLM снаружи → загружает ответ .docx → деанонимизирует → экспортирует финальный .docx. Весь цикл без единой ошибки.

### 1.1 Улучшение качества анонимизации

**Что:** довести NER pipeline до уровня, когда он надёжно находит все PII в типичном российском юридическом документе.

**Задачи:**
- Переключить spaCy модель с `ru_core_news_sm` на `ru_core_news_lg` (точнее NER)
- Расширить regex-паттерны: проверить покрытие на реальных юрдокументах (банковские реквизиты, КПП, БИК, расчётные счета, кадастровые номера)
- Настроить score thresholds для GLiNER: текущие пороги могут пропускать сущности
- Добавить тест-сюиту на реальных (или приближённых к реальным) юридических шаблонах — договоры, претензии, доверенности
- Проверить работу pymorphy3/Natasha нормализации на склонениях ФИО в разных падежах

**Критерий:** ≥95% recall на тест-сюите юрдокументов. Лучше замаскировать лишнее (юрист снимет галочку), чем пропустить.

### 1.2 Загрузка ответного документа

**Что:** юрист может загрузить .docx, полученный от LLM, обратно в VELUM для деанонимизации. Это **вторая точка входа** — не анонимизация, а деанонимизация.

**Задачи:**
- Backend: новый endpoint `POST /api/sessions/{session_id}/import-response` — принимает .docx, парсит, возвращает текст + структуру
- Frontend: кнопка «Загрузить ответ LLM» на правой панели (или в header) — доступна только при наличии активной сессии с mapping table
- UI: после загрузки split-screen переключается: слева — анонимизированный ответ LLM, справа — деанонимизированный (превью)

### 1.3 Деанонимизация .docx

**Что:** обратная подстановка плейсхолдеров → реальных значений внутри .docx файла с сохранением форматирования.

**Задачи:**
- Backend: новый сервис `docx_deanonymize.py` (зеркало `docx_export.py`, но в обратную сторону)
  - Проход по всем параграфам/таблицам/header/footer .docx
  - Замена `[ЛИЦО_1]` → `Иванов Иван Иванович` и т.д. с сохранением форматирования run'а
  - **Fuzzy matching:** распознавание искажённых плейсхолдеров (`[ЛИЦО 1]`, `ЛИЦО_1`, `[Person_1]`) — нормализация перед поиском в mapping table
  - **Обнаружение неизвестных плейсхолдеров:** если встречен `[ЛИЦО_5]`, которого нет в реестре — включить в response как `unresolved` с позицией
- Backend: endpoint `POST /api/sessions/{session_id}/deanonymize-docx` — принимает .docx, возвращает деанонимизированный .docx + список unresolved
- Frontend: отображение unresolved плейсхолдеров как интерактивных плашек — юрист кликает и вводит значение вручную

### 1.4 Экспорт деанонимизированного .docx

**Что:** юрист скачивает финальный документ с реальными данными.

**Задачи:**
- Backend: endpoint `POST /api/sessions/{session_id}/export-deanonymized` — возвращает .docx после подстановки (включая ручные значения для unresolved)
- Frontend: кнопка «Экспорт» на правой панели
- Проверка перед экспортом: если остались unresolved плейсхолдеры без заполненных значений — предупреждение (не блокирующее)

### 1.5 Persistence сессий

**Что:** mapping table и состояние сессии сохраняются на диск. Юрист может закрыть VELUM и вернуться позже.

**Задачи:**
- Backend: реализовать `SessionStore` — сериализация сессии (session_id, mapping table encrypted, document metadata, timestamps) в файл на диске
- Формат: один JSON/SQLite файл на сессию в `data/sessions/`, mapping table внутри — зашифрованный blob (AES-256-GCM)
- Backend: при старте — загрузка активных сессий с диска
- Backend: TTL — 7 дней по умолчанию, настраиваемо
- Frontend: на Home экране — список активных сессий с возможностью «Продолжить»
- Frontend: при открытии сессии — восстановление split-screen с последним состоянием

### 1.6 Полировка UI

**Что:** довести существующий UI до production-ready.

**Задачи:**
- Убедиться, что split-screen работает стабильно на разных размерах экрана
- Проверить entity overlay performance на больших документах (100+ страниц)
- Добавить loading state для длительных операций (анонимизация, деанонимизация)
- Error handling: понятные сообщения при ошибках (файл не .docx, файл повреждён, pipeline не запустился)
- Проверить metadata scrub на edge cases (embedded images с EXIF, custom XML parts)

### 1.7 Acceptance testing

**Что:** end-to-end тест полного round-trip на реалистичных данных.

**Задачи:**
- Подготовить 5–10 тестовых .docx (различные типы: договор, претензия, доверенность, протокол) с синтетическими PII
- Для каждого: анонимизировать → экспортировать → имитировать ответ LLM (вручную модифицировать анонимизированный) → загрузить ответ → деанонимизировать → экспортировать → проверить
- Проверить: (a) все PII замаскированы, (b) форматирование сохранено, (c) обратная подстановка корректна, (d) метаданные очищены, (e) fuzzy matching работает, (f) unresolved обнаруживаются
- Результаты задокументировать в `docs/TESTING.md`

## Phase 2 — Карусель, diff, multi-doc

**Цель:** улучшить тот же round-trip, не добавляя новых каналов.

### 2.1 Карусель документов

- Split-screen показывает 2 из 4 документов: оригинал, аноним, аноним-ответ, деаноним-ответ
- Горизонтальная навигация влево-вправо (кнопки или жесты)
- Индикатор текущей пары (breadcrumb / dots)
- Анимация переключения (slide)

### 2.2 Diff с оригиналом

- Сравнение деанонимизированного ответа с оригинальным документом
- Подсветка: вставки (зелёный), удаления (красный), замены (жёлтый)
- Accept / reject каждой правки по отдельности
- Экспорт с принятыми правками как финальный .docx
- Условный рендеринг: кнопка «Сравнить с оригиналом» видна только если обнаружено семантическое сходство документов

### 2.3 Multi-document сессии

- Загрузка нескольких .docx в одну сессию
- Единый EntityRegistry для всех документов сессии
- Навигация между документами в левом sidebar
- Групповой экспорт: все анонимизированные документы одним архивом
- Групповая деанонимизация: несколько ответов LLM загружаются и деанонимизируются по общему реестру

### 2.4 Итеративная работа

- Возможность загрузить второй (третий, ...) ответ LLM в ту же сессию
- Реестр пополняется, если в новом ответе появились новые плейсхолдеры
- История раундов: юрист видит, сколько раундов было, может вернуться к любому

### 2.5 UX polish — EPAM colors (feedback from 2026-04-14 testing)

Reference: скриншот BizLink-подобного дашборда, который юрист приложил как образец визуального стиля (светлая тема, чёрный primary, серые карточки, акцент на типографике).

- **Sidebar sessions:** каждая запись сессии в левом tray показывает **только дату и время** подачи. Убрать имя файла / дополнительные метаданные из кликабельной строки — перенести их в tooltip или в карточку при hover.
- **Save & resume across stages:** юрист может сохранить сессию на любом шаге (анонимизация / импорт ответа / деанонимизация / unresolved) и вернуться к ней позже с полным сохранением состояния — в том числе ручных правок entity (accept/reject/rename, добавленные пользовательские сущности, введённые вручную resolutions). Текущий SQLite-store это уже даёт для стадии 1; нужно расширить на фазы импорта и деанонимизации + UI «Continue from where you left off».
- **Zoom indicator ephemeral:** процент масштабирования документа отображается в **нижнем правом углу правой панели**, появляется только во время изменения масштаба и плавно fade-out через ~1 с после последнего события (паттерн Apple — HUD). Убрать постоянно видимый индикатор из subheader'а (оставить только как accessible fallback для screen readers).
- **EPAM color system:** перепройти все базовые токены (`--color-brand`, `--text-primary`, `--border`, highlight-цвета сущностей и diff) под брендбук ЕПАМ (черный, белый, нейтральные серые, один акцент-оранжевый). Создать отдельный ADR «VELUM UI = EPAM brand» с набором CSS variables и обновить `globals.css` одним коммитом. Ссылка на образец стиля — в `docs/assets/` (добавить скриншот).

## Phase 3 — Встроенный LLM-чат

**Цель:** убрать ручное копирование между VELUM и LLM.

### 3.1 Настройки API-ключей

- Экран настроек: поля для API-ключей Claude, GPT, Gemini
- Хранение: зашифровано локально (OS keychain или AES на диске)
- Проверка ключа: кнопка «Test connection»

### 3.2 LLM-адаптеры

- Нативные адаптеры (не unified shim) для Claude, GPT, Gemini
- У Claude уже есть адаптер — расширить/стабилизировать
- Добавить GPT adapter (OpenAI SDK)
- Добавить Gemini adapter (Google GenAI SDK)
- Поддержка streaming (WebSocket уже есть)

### 3.3 UI режим чата

- Переключение между «режим анонимизации» (split-screen) и «режим чата» (документ + чат-панель)
- Чат-панель: input, история сообщений, выбор провайдера
- Автоматическая анонимизация запроса перед отправкой
