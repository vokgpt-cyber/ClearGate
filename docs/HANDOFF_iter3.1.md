## Что мы решаем прямо сейчас (iter3.2)

Два бага, которые **iter3.1 не пофиксил, хотя пытался**:

### Баг №1 — попап «Анонимизировать» не появляется при выделении

**Формальное требование (дословно от пользователя):**
> When a text (one or multiple letters/words) gets selected the pop up
> window shall appear offering to anonymize selected text.

То есть: **любое** непустое выделение — хоть одна буква, хоть одно
слово, хоть целый абзац — ДОЛЖНО немедленно вызывать всплывающее окно
с предложением анонимизировать выделенный текст. Никаких
пороговых значений длины, никаких задержек, никаких условий «только
если выделение больше N символов». Одна буква выделена — попап уже
всплыл.

**Ожидаемое поведение:** юрист выделяет произвольный кусок текста
мышкой в **любой** панели (оригинал или анонимизированная версия), и
под курсором (точка отпускания мыши) всплывает маленькая панелька с
кнопкой **«Анонимизировать»**. Клик раскрывает выбор типа сущности
(Лицо / Организация / Место / Счёт / Номер договора / Дата). После
выбора сущность добавляется в `EntityRegistry` и подсвечивается в обеих
панелях. Escape закрывает попап. Поведение должно быть как в
Google Docs / Notion / Harvey.AI — мгновенным, без задержек и
мерцания.

**Фактическое поведение:** выделение работает (текст выделяется), но
попап не появляется **нигде** — ни слева, ни справа.

**Что уже пробовали (и провалились) в iter3.1:**
1. Переписали обработчик с `selectionchange` на `mouseup` на документе.
2. Поменяли якорь попапа с прямоугольника выделения на координаты
   курсора (`e.clientX, e.clientY`).
3. Добавили поддержку правой панели через `rightOffsetsToLeft` в
   `entity-overlay.ts`.
4. Добавили `onMouseDown → preventDefault` на корне попапа, чтобы клик
   не сбрасывал выделение.
5. Убрали `selectionchange`-листенер полностью.

Попап всё равно не появляется. Это значит: **фикс не в ручках, а в
архитектуре** — что-то в цепочке «выделение → событие → хендлер →
стейт → рендер → DOM» обрывается, и мы не знаем где.

**Жёсткое правило для тебя (из памяти, раздел
`feedback_diagnose_before_patch.md`):** НЕ пиши четвёртый
инкрементальный фикс по наитию. Сначала **диагностика всей цепочки
событий от начала до конца**:

1. Прочитай целиком:
   - `frontend/src/components/SelectionToolbar.tsx` (~158 строк)
   - `frontend/src/components/SplitWorkspace.tsx` (~705 строк) — особенно
     `useEffect` с обработчиком `mouseup` и JSX-рендер
     `<SelectionToolbar>`
   - `frontend/src/lib/entity-overlay.ts` — `rightOffsetsToLeft` и
     `DocxAnchorMap.rangeToOffsets`
2. Расставь `console.log` на каждой границе цепочки: `mouseup fired` →
   `target pane detected` → `range extracted` → `offsets resolved` →
   `setSelection() called` → `SelectionToolbar mounted` → `popover
   visible in DOM`.
3. Попроси меня один раз выделить текст и прислать скриншот консоли
   DevTools.
4. **Только потом** правь ровно то место, где цепочка оборвалась.

Никаких «скорее всего это рендер-гвард, давай попробую» без
подтверждения.

### Баг №2 — zoom применили не к тому элементу

В iter3.1 я просил «уменьшить масштаб интерфейса до ~80% от текущего».
Поставили `zoom: 0.7` на `.velum-docx-wrapper` в
`frontend/src/app/globals.css` (строка ~707). Это оказался **документ
внутри панели**, а не shell приложения — в результате мельче стал
**только текст договора**, а сайдбар VELUM, шапка, строка подключения,
нижняя панель сущностей остались крупными.

**Я хотел ровно обратного:** интерфейс (chrome приложения — сайдбар,
шапка, entity legend) должен стать мельче, как в desktop-инструментах
класса Harvey.AI / Linear / Figma, а сам документ — остаться в
комфортном для чтения размере.

**Направление фикса:**
- Найти корневой shell-элемент (вероятно `.velum-shell` или React-root)
  и посмотреть, что из интерфейсных компонентов наследует размеры от
  него.
- Либо уменьшить `font-size` / `padding` сайдбара, шапки и бара
  сущностей напрямую через CSS (чище для hit-testing), либо применить
  `zoom` к chrome-контейнеру и компенсировать его на документе.
- Вариант с прямой регулировкой через CSS-переменные темы **обычно
  чище**, чем `zoom`. Тема VELUM уже на CSS custom properties — см.
  `frontend/src/app/globals.css`.
- Удалить `zoom: 0.7` с `.velum-docx-wrapper`.

Эту правку можно делать **после** диагностики бага №1, но снимай
отдельный snapshot для каждой — не смешивай в одном коммите.

## Как работать в этом проекте

1. Перед любыми изменениями прочитай:
   - `CLAUDE.md` в корне
   - `backend/CLAUDE.md` или `frontend/CLAUDE.md` в зависимости от
     того, что трогаешь
   - Релевантные ADR в `docs/adr/`
2. Следуй стилю кода из `docs/CODE_STYLE.md`.
3. Коммиты — Conventional Commits (`feat(frontend): ...`, `fix(frontend):
   ...`).
4. После каждой значимой правки, которая прошла `tsc` и визуальную
   проверку — автоматически вызывай `scripts/snapshot.ps1 -Message
   "..."`. Я не хочу управлять снапшотами вручную.
5. Никогда не логируй оригинальный текст документов, mapping table или
   ключи (модель угроз — см. `docs/SECURITY_MODEL.md`).
6. Никогда не добавляй unified LLM shim'ы (LiteLLM и т.п.) — только
   нативные адаптеры (ADR-0006).
7. Если файл больше ~300 строк — правь через bash heredoc, Edit/Write
   молча обрезают длинные файлы (см. память `feedback_file_tooling.md`).
