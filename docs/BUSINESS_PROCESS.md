# VELUM — Бизнес-процесс работы юриста

> Версия: 1.0
> Согласовано: 13 апреля 2026
> Статус: утверждён как baseline для разработки

---

## Что такое VELUM с точки зрения юриста

VELUM — это инструмент, который делает две вещи: **анонимизирует** документ перед отправкой в LLM и **деанонимизирует** ответ LLM обратно. Всё остальное — производные от этих двух операций. VELUM не заменяет LLM, не заменяет рабочее место юриста и не является чат-ботом. Это **фильтр безопасности**, через который проходят документы по пути к LLM и обратно.

---

## Основной процесс (Phase 1 — core)

### Шаг 1. Юрист готовит задачу

Юрист берёт документ (например, договор от подрядчика), изучает его и формулирует цель:

- **Анализ:** понять, о чём договор, выявить ключевые условия и риски.
- **Рекомендации:** получить от LLM предложения по дальнейшим шагам.
- **Ответный документ:** подготовить через LLM новый документ (правки к договору, ответ на претензию и т.д.).

Эта цель определяет, понадобится ли юристу деанонимизация на выходе (см. шаги 5а и 5б).

### Шаг 2. Загрузка и анонимизация

Юрист загружает документ (.docx) в VELUM и нажимает «Анонимизировать».

VELUM прогоняет документ через трёхслойный pipeline (regex → NER → LLM-верификация) и заменяет все найденные персональные и чувствительные данные на плейсхолдеры:

- ФИО → `[ЛИЦО_1]`, `[ЛИЦО_2]`, ...
- Организации → `[ОРГАНИЗАЦИЯ_1]`, ...
- Адреса → `[АДРЕС_1]`, ...
- ИНН, ОГРН, паспорта, счета, телефоны, email → соответствующие плейсхолдеры

Результат отображается в split-screen: **слева — оригинал**, **справа — анонимизированная версия**. Каждая замена подсвечена цветной плашкой. Юрист видит полный список найденных сущностей и может:

- **Снять галочку** с любой сущности, если считает, что её не нужно маскировать (например, название публичной компании, даты, суммы — то, без чего LLM не сможет дать полезный ответ).
- **Добавить** сущность вручную, если VELUM что-то пропустил.

**Принцип:** всё, что VELUM считает PII, маскируется по умолчанию. Юрист только снимает лишнее, а не добавляет нужное. Privacy by default.

Одновременно VELUM:
- Создаёт **mapping table** (`[ЛИЦО_1]` ↔ `Иванов Иван Иванович`) и шифрует её (AES-256-GCM) в памяти.
- Сохраняет сессию на диск, чтобы юрист мог вернуться позже для деанонимизации.
- Очищает **метаданные** документа (автор, организация в properties, комментарии с именами, timestamps) — всё, что может утечь помимо текста.

### Шаг 3. Проверка анонимизации

Юрист просматривает split-screen и убеждается, что:
- Все чувствительные данные замаскированы.
- Ничего лишнего не замаскировано (если да — снимает галочки).
- Документ читается осмысленно с плейсхолдерами.

### Шаг 4. Экспорт анонимизированного документа

Юрист нажимает «Экспорт» и получает .docx файл с плейсхолдерами вместо PII. **Форматирование оригинала сохраняется полностью** — шрифты, таблицы, нумерация, колонтитулы. Меняется только текст в местах замены.

Юрист самостоятельно загружает этот файл в любую LLM, которая ему нравится (Claude, ChatGPT, Gemini), и работает с ней как обычно.

### Шаг 5. Работа с LLM (вне VELUM)

Далее юрист работает с LLM самостоятельно. Результат зависит от цели:

**Путь 5а — консультация (без деанонимизации).**
Юрист задаёт вопросы, получает анализ, рекомендации, разъяснения. Ответ LLM содержит плейсхолдеры (`[ЛИЦО_1]`, `[ОРГАНИЗАЦИЯ_2]`), но юрист понимает, кто есть кто — оригинал перед глазами. Деанонимизировать не нужно. Процесс завершён.

**Путь 5б — документ (требуется деанонимизация).**
Юрист просит LLM подготовить документ (правки к договору, ответ на претензию, меморандум). LLM возвращает документ с теми же плейсхолдерами, что были в загруженном файле. Юрист скачивает этот документ и переходит к шагу 6.

### Шаг 6. Загрузка ответа и деанонимизация

Юрист возвращается в VELUM **в ту же сессию**, в которой делал анонимизацию. Загружает .docx файл, полученный от LLM. Нажимает «Деанонимизировать».

VELUM выполняет обратную подстановку по mapping table: `[ЛИЦО_1]` → `Иванов Иван Иванович`, `[ОРГАНИЗАЦИЯ_2]` → `ООО Ромашка` и т.д.

При деанонимизации VELUM:

- **Fuzzy matching плейсхолдеров.** LLM может исказить формат: написать `[ЛИЦО 1]` вместо `[ЛИЦО_1]`, или `ЛИЦО_1` без скобок, или `[Person_1]`. VELUM распознаёт такие варианты и заменяет правильно.
- **Обнаружение новых сущностей.** LLM может придумать плейсхолдер, которого не было в оригинале (например, `[ЛИЦО_5]`). VELUM помечает такие места: «[ЛИЦО_5] — не найден в реестре сессии. Введите значение вручную или оставьте как есть.» Юрист решает сам.

Результат отображается в split-screen: **слева — анонимизированный ответ LLM**, **справа — деанонимизированная версия**.

### Шаг 7. Проверка деанонимизации

Юрист просматривает split-screen и убеждается, что:
- Все плейсхолдеры заменены корректно.
- Неизвестные плейсхолдеры (если были) обработаны — заполнены вручную или помечены.
- Текст читается осмысленно.

### Шаг 8. Экспорт финального документа

Юрист нажимает «Экспорт» и получает финальный .docx с реальными данными. Форматирование сохранено. Документ готов к использованию — отправке клиенту, подаче в суд, обсуждению с коллегами.

## Расширения процесса (Phase 2–4)

Ниже — функционал, который расширяет базовый процесс. Порядок фаз отражает приоритет: сначала углубляем core, потом добавляем новые каналы.

### Phase 2 — Карусель документов, diff, multi-doc

**Карусель документов.** На каждом этапе split-screen показывает два документа из четырёх возможных: (1) оригинал, (2) анонимизированная версия, (3) анонимизированный ответ LLM, (4) деанонимизированный ответ. Юрист может прокручивать пары влево-вправо:

```
[1 оригинал] ↔ [2 аноним]        — этап анонимизации
[3 аноним-ответ] ↔ [4 деаноним]  — этап деанонимизации
[4 деаноним] ↔ [1 оригинал]      — этап сравнения
```

**Diff с оригиналом.** На последнем шаге карусели юрист видит деанонимизированный ответ LLM рядом с оригинальным документом. Различия подсвечены: вставки зелёным, удаления красным, изменения жёлтым. Возможность принять или отклонить каждую правку по отдельности. Эта функция применима, когда LLM вернул модифицированную версию исходного документа. Когда ответ — совершенно другой документ (ответ на претензию и т.д.), diff не используется.

**Multi-document сессии.** Юрист может загрузить несколько связанных документов в одну сессию (договор + допсоглашение + переписка). Все документы анонимизируются с **единым реестром**: `[ЛИЦО_1]` = Иванов во всех документах сессии. Деанонимизация работает так же — по общему реестру.

**Итеративная работа.** Юрист может в одной сессии выполнить несколько раундов: загрузить ответ LLM, деанонимизировать, снова загрузить уточнённый ответ, деанонимизировать повторно. Реестр сессии сохраняется между раундами.

### Phase 3 — Встроенный LLM-чат

**Настройка API-ключей.** В настройках VELUM юрист вводит свои API-ключи для Claude, GPT, Gemini. Ключи хранятся локально, зашифрованы.

**Отправка из VELUM.** Вместо экспорта и ручной загрузки в LLM, юрист может отправить анонимизированный документ в выбранную LLM прямо из VELUM. UI переключается в режим чата: анонимизированный документ + чат-панель. Ответы LLM автоматически деанонимизируются.

**Prompt library.** Библиотека шаблонных промптов для типовых задач: «Анализ договора», «Подготовка ответа на претензию», «Выделение ключевых условий». Юрист выбирает шаблон, VELUM подставляет правильный контекст.

**Путь 5а → документ.** Если юрист получил текстовый ответ в чате и хочет превратить его в документ — кнопка «Сохранить как документ», деанонимизация, экспорт.

### Phase 4 — Расширение форматов и advanced

**Дополнительные форматы.** Поддержка .pdf (с OCR), .eml, .txt, .md на входе. На выходе — всегда .docx (или формат входного документа, если возможно).

**Advanced фичи.** По результатам обратной связи от юристов после Phase 1–3.

## Ключевые инварианты (действуют на всех фазах)

1. **Privacy by default.** Всё, что VELUM считает PII, маскируется. Юрист может только снять маску, но не обязан добавлять.
2. **Оригинал не модифицируется.** VELUM никогда не изменяет загруженный файл. Работа идёт с копиями.
3. **Mapping table зашифрован.** AES-256-GCM, ключ в памяти, на диске — шифрованный blob. Никогда не логируется, не отправляется наружу.
4. **Сессия persistent.** Юрист может закрыть VELUM, вернуться через час или день, и продолжить работу в той же сессии с тем же реестром.
5. **Форматирование сохраняется.** Экспортированный .docx идентичен оригиналу по форматированию. Меняется только текст в местах замены.
6. **Метаданные очищаются.** При экспорте анонимизированного документа удаляются: автор, организация, комментарии с именами, timestamps, thumbnail.
7. **Нет отправки без анонимизации.** В Phase 3, когда появится встроенный LLM-чат, любой контент проходит через анонимизацию перед отправкой. API для «послать raw» физически отсутствует.

## Визуальная схема процесса

```
Phase 1 (core):

  ┌──────────┐     ┌──────────────┐     ┌───────────┐
  │ Оригинал │────▶│ VELUM: аноним│────▶│ Экспорт   │
  │ .docx    │     │ + проверка   │     │ аноним.   │
  └──────────┘     └──────────────┘     │ .docx     │
                                        └─────┬─────┘
                                              │
                          юрист работает в LLM самостоятельно
                                              │
                                        ┌─────▼─────┐
  ┌──────────┐     ┌──────────────┐     │ Ответ LLM │
  │ Экспорт  │◀────│ VELUM: деано-│◀────│ аноним.   │
  │ финальный│     │ ним + провер.│     │ .docx     │
  │ .docx    │     └──────────────┘     └───────────┘
  └──────────┘

Phase 2: + карусель + diff + multi-doc + итерации
Phase 3: + встроенный LLM-чат + prompt library
Phase 4: + .pdf, .eml и другие форматы
```
