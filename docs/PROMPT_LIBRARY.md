# Prompt Library — VELUM

Готовые промпты для работы с Claude Code на проекте VELUM. Скопируй нужный промпт, при необходимости подставь параметры.

## Принципы хороших промптов для Claude Code

1. **Указывай контекст** — какой файл/задача, какие ADR прочитать
2. **Будь конкретным** — не «улучши код», а «добавь обработку случая X»
3. **Указывай acceptance criteria** — как понять, что задача выполнена
4. **Проси показать diff** — перед коммитом
5. **Ссылайся на task files** — `docs/tasks/NN-name.md` уже содержит структурированный промпт

## Отладка и поиск багов

### Тест падает, разобраться

```
Тест tests/services/test_entity_registry.py::test_fuzzy_match_russian_names падает.

Запусти его с `pytest -v --tb=long` и разберись:
1. Что именно он проверяет?
2. Что фактически возвращает код?
3. Где источник проблемы — в логике или в тесте?
4. Предложи фикс с обоснованием.

Не вноси изменения в код без моего подтверждения.
```

### Performance issue

```
NER pipeline тормозит на больших документах (>50 страниц).

Запусти профилирование на synthetic корпусе из tests/fixtures/large_doc.json:
1. Замерь время каждого слоя (regex / spaCy / GLiNER / LLM verifier)
2. Найди узкое место
3. Предложи 2-3 варианта оптимизации с trade-offs
4. НЕ внедряй ничего без обсуждения

Purpose: понять что оптимизировать, а не сразу всё переписывать.
```

### Отладка через логи

```
Анонимизация документа возвращает странные результаты — некоторые ИНН не находятся.

1. Включи DEBUG логирование в backend (но БЕЗ оригинального текста!)
2. Запусти анонимизацию на проблемном документе (path: tests/fixtures/problem_doc.txt — синтетические данные)
3. Покажи мне трейс работы pipeline
4. Гипотезы о причине

Напоминаю: НЕ логировать содержимое документа. Только метаданные:
позиции, типы, scores, source layer.
```

## Документация

### Обновление CHANGELOG

```

- Fixed (fix)

```

### Создание ADR

```
Я хочу зафиксировать решение использовать Redis вместо in-memory dict
для session storage в Final конфигурации.

Создай ADR-0008 в docs/adr/ по шаблону из docs/adr/README.md.

Контекст:
- На Final 50-200+ пользователей одновременно
- Нужна персистентность сессий между перезапусками pods
- Нужна возможность кросс-pod sharing
- В Alpha/MVP остаётся in-memory dict (без изменений)

Альтернативы которые я рассматривал:
- PostgreSQL — overkill для key-value
- Memcached — нет встроенной шифрования
- Etcd — overkill, заточен под config
- Redis — выбран

Напиши ADR со всеми разделами шаблона.
```

```
Сравни с текущим содержимым docs/API.md и покажи diff. НЕ перезаписывай

```

## Антипаттерны (не делай так)

### ❌ Слишком общий промпт

```
Сделай VELUM лучше.
```

### ❌ Без контекста

```
Добавь обработку ошибок.
```

### ❌ Разрешение на всё

```
Делай что хочешь, главное чтобы работало.
```

### ✅ Хороший промпт всегда содержит

1. **Что** — конкретная задача
2. **Где** — файлы / модули
3. **Почему** — контекст и обоснование
4. **Как** — ограничения, стандарты, ADR
5. **Acceptance criteria** — как понять что готово
6. **Что НЕ делать** — границы автономии
