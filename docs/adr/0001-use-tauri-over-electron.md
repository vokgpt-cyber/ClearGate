# ADR-0001: Use Tauri 2 over Electron for desktop shell

**Дата:** 2026-04-09
**Статус:** Accepted
**Авторы:** EPAM Legal Dev

## Контекст

CLEARGATE — desktop-приложение, которое должно работать на Windows 11 и потенциально на macOS/Linux. Нужен desktop shell, в который можно встроить React/Next.js фронтенд и обеспечить взаимодействие с локальным Python-бэкендом.

Два очевидных кандидата:
- **Electron** — индустриальный стандарт, на нём VS Code, Slack, Discord, Notion. Огромная экосистема, много примеров, простота развёртывания.
- **Tauri 2** — Rust-shell с использованием системного WebView. Молодой, но быстро набирающий популярность.

Контекст CLEARGATE:
- Чувствительность данных (адвокатская тайна) → нужна максимальная изоляция и минимальная attack surface
- Solo-разработчик → нужен минимум boilerplate
- Использование на корпоративных машинах ЕПАМ → размер инсталлятора и потребление ресурсов имеют значение
- Будущее развёртывание на сотнях машин → системный WebView предсказуемо обновляется через ОС

## Решение

Использовать **Tauri 2.10+** как desktop shell для CLEARGATE.

## Альтернативы, которые рассматривались

### Electron
- ✅ Зрелая экосистема, тонны примеров
- ✅ Простой для новичков
- ❌ Размер инсталлятора 100+ МБ против 2–10 МБ у Tauri
- ❌ Idle потребление RAM 150–300 МБ против ~30 МБ у Tauri
- ❌ Каждое приложение тащит свою копию Chromium → больше attack surface
- ❌ Безопасность по умолчанию слабее (всё разрешено, нужно явно отключать)

### Web app + браузер
- ✅ Самая простая модель развёртывания
- ❌ Невозможно обеспечить on-premise изоляцию для одного юриста на ноутбуке
- ❌ Сложнее интегрироваться с локальной файловой системой
- ❌ Не подходит под концепцию desktop-инструмента

### Native (Qt / WPF / SwiftUI)
- ✅ Максимальная производительность
- ❌ Solo-разработчик не пишет на C++/C#/Swift
- ❌ Невозможно переиспользовать React-компоненты
- ❌ В разы больше времени на разработку

## Последствия

### Положительные
- Размер дистрибутива в десятки раз меньше Electron
- Idle потребление памяти в 5–10 раз меньше
- **Capability-based security**: всё запрещено по умолчанию, разработчик явно открывает только нужные API. Это критически важно для приложения с чувствительными данными.
- Rust-ядро компилируется в нативный бинарник, сложнее реверс-инжинирить
- Использование системного WebView (Edge WebView2 на Windows) → автообновления через ОС, единообразное поведение
- Отличная интеграция с Next.js через `output: 'export'`

### Отрицательные / компромиссы
- Меньшая экосистема → иногда нужно искать альтернативы Electron-only пакетам
- Системный WebView означает разные движки на разных ОС (Edge на Windows, Safari на macOS, WebKitGTK на Linux). Могут быть рендеринг-различия.
- Tauri 2 относительно молод (релиз октябрь 2024) → меньше готовых рецептов
- Требует Rust toolchain для разработки (не критично, ставится один раз)
- Solo-разработчик не знает Rust → но Tauri shell минимален, 95% работы в TypeScript/Python

### Нейтральные
- Нужна capability-конфигурация для каждого Tauri API → больше boilerplate, но это прямое следствие модели безопасности
