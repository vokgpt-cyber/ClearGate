# CLEARGATE — Щит адвокатской тайны в эпоху искусственного интеллекта

## Концепт-документ приложения для безопасной работы юристов АБ ЕПАМ с крупнейшими LLM через автоматическую анонимизацию данных

**Версия:** 2.0 | **Дата:** 9 апреля 2026 | **Статус:** Концепт / Техническое задание

---

## Резюме для руководства

**CLEARGATE** — on-premise приложение для юристов АБ ЕПАМ, которое решает фундаментальную проблему: **использовать всю мощь ведущих LLM мира (Claude, GPT, Gemini) без риска утечки клиентских данных и нарушения адвокатской тайны**. Приложение автоматически обнаруживает и заменяет все чувствительные сущности (ФИО, компании, суммы, ИНН, паспортные данные и десятки других типов) на нейтральные плейсхолдеры перед отправкой текста в облачные LLM, а затем автоматически восстанавливает оригинальные данные в полученном ответе.

Это четвёртое приложение экосистемы ЕПАМ, дополняющее **VERITAS** (транскрибация), **EPAMOS** (CRM/биллинг) и **CONCLAVE** (видеозвонки). В отличие от существующих решений на рынке, CLEARGATE разработан специально для российского юридического контекста — с поддержкой русскоязычного NER и распознаванием ИНН/ОГРН/СНИЛС/паспортных данных.

Приложение проектируется в **трёх конфигурациях развёртывания** — от эксперимента на ноутбуке до продакшн-кластера на серверах ЕПАМ. Код один и тот же, масштабируются только модели и инфраструктура.

## А. Название приложения

### Семь кандидатов

Каждое название исследовано по этимологии, семантике и соответствию экосистеме, где уже присутствуют VERITAS (латынь: «истина»), EPAMOS (греческий стиль), CONCLAVE (латынь: «запертая комната»).

**1. CLEARGATE** ⭐ (рекомендация)
Латинское *vēlum* — «завеса, покров, вуаль». Прямая метафора: завеса между чувствительными данными и внешним миром. Слово короткое, элегантное, легко произносится на любом языке. Фонетически перекликается с VERITAS. Завеса в храме, завеса тайны — мощные ассоциации для юридического контекста.

**2. AEGIS**
Греческое *aigís* (αἰγίς) — божественный щит Зевса и Афины. «Под эгидой» — устоявшееся юридическое выражение. Немедленно узнаваемо, коннотация абсолютной защиты. Связь с EPAMOS через греческие корни.

**3. ARCANUM**
Латинское *arcānum* — «тайна, секрет» (от *arca* — «сундук, хранилище»). Буквально «то, что заперто и скрыто». Идеально описывает функцию приложения. Отличительное, запоминающееся, элегантное.

**4. PERSONA**
Латинское *persōna* — изначально «маска» в римском театре. Анонимизация — это надевание масок на данные. Современное значение добавляет глубину: управление идентичностями. Мгновенно понятно во всех культурах.

**5. CUSTOS**
Латинское *custōs* — «страж, хранитель». Приложение выступает хранителем данных. Юридический термин «кустодия» (custody) — общеизвестен. Короткое, мощное, профессиональное.

**6. OBSCURA**
Латинское *obscūra* — «тёмная, скрытая, затенённая». Через «camera obscura» слово широко известно. Прямо описывает функцию: затемнение/сокрытие данных. Элегантное латинское звучание.

**7. TEGMEN**
Латинское *tegmen* — «покров, щит, защита» (от *tegere* — «покрывать»). Родственно слову «protect» (pro-tegere). Редкое, отличительное, научно-точное.

### Рекомендуемое название: CLEARGATE

CLEARGATE выбрано как основное по совокупности критериев. Оно точнее всего передаёт суть приложения (завеса между данными и LLM), стилистически гармонирует с VERITAS и CONCLAVE, легко запоминается и произносится на русском и английском. Слоган: **«Завеса, за которой — адвокатская тайна»**.

## Б. Архитектура

### Трёхслойный pipeline анонимизации

CLEARGATE использует три последовательных уровня обнаружения чувствительных данных, каждый из которых закрывает слабости предыдущего.

**Уровень 1: Regex-паттерны (Presidio PatternRecognizer)**
Самый быстрый и точный слой для структурированных данных. Каждый российский идентификатор имеет чёткий числовой формат с контрольными суммами.

| Сущность | Формат | Метод валидации |
|----------|--------|-----------------|
| ИНН (физ. лицо) | 12 цифр | Контрольные суммы 11-й и 12-й цифры |
| ИНН (юр. лицо) | 10 цифр | Контрольная сумма 10-й цифры |
| ОГРН | 13 цифр | Остаток от деления на 11 |
| СНИЛС | XXX-XXX-XXX XX | Контрольная сумма по алгоритму ПФР |
| Паспорт РФ | XXXX XXXXXX (серия + номер) | Проверка допустимых серий |
| Банковский счёт | 20 цифр | Контрольный ключ по БИК |
| Телефон | +7XXXXXXXXXX (варианты) | Regex с нормализацией |
| Email | стандартный regex | RFC 5322 |
| Даты | ДД.ММ.ГГГГ | Валидация допустимых дат |
| Номер дела | А40-12345/2026 | Regex арбитражных/судебных номеров |

**Уровень 2: NER-модели (нейросетевые + rule-based)**
Обнаружение неструктурированных сущностей: имена, компании, адреса, должности.

Основная модель — **spaCy ru_core_news_lg** (F1 ≈ 93% на бенчмарке Nerus, распознаёт PER/LOC/ORG, интегрируется напрямую с Presidio как NLP-engine). Дополнительно — **GLiNER** (Medium ~440 МБ для Alpha, Large для MVP/Final) для кастомных типов сущностей через zero-shot подход: достаточно задать метки [«должность», «сумма контракта», «наименование суда», «кодовое название проекта»] — и модель их найдёт без дообучения. Для rule-based извлечения структурированных фактов из русского текста — **Yargy** (часть экосистемы Natasha).

**Уровень 3: Локальная LLM для сложных случаев**
Для документов, где контекст неоднозначен, запускается локальная LLM через Ollama. Выбор модели зависит от конфигурации:

- **Alpha (RTX 4060, 8 ГБ)**: Qwen 2.5 **7B** Q4_K_M (~4.8 ГБ VRAM) — обучена на русском, отлично генерирует JSON
- **MVP (RTX 3090, 24 ГБ)**: Qwen 2.5 **32B** Q4 (~20 ГБ) или **14B FP16** — качество уровня GPT-4o на русском
- **Final (2–4× RTX 6000 Ada / A100 / H200)**: Qwen 2.5 **72B FP16**, DeepSeek-V3, или собственная fine-tuned модель на корпусе ЕПАМ

LLM решает задачи, недоступные предыдущим слоям: кореференция («он», «указанная компания» → привязка к конкретной сущности), сложные составные сущности («генеральный директор ООО «Ромашка» Иванов И.И.»), контекстная верификация обнаруженных сущностей.

### Microsoft Presidio как оркестратор

**Presidio** (v2.2, Microsoft, open-source) выступает центральным фреймворком, объединяющим все три уровня. Из коробки он не поддерживает русский язык, но спроектирован для расширения. Конфигурация для CLEARGATE: Presidio Analyzer получает русский spaCy как NLP-engine, кастомные PatternRecognizer для российских идентификаторов с русскими контекстными словами («паспорт», «ИНН», «телефон»), а GLiNER подключается через официальный Presidio-сэмпл интеграции. Presidio Anonymizer затем применяет согласованные замены с использованием консистентного маппинга.

### Стратегия консистентной замены сущностей

Ключевое требование — **«Иван Петров» должен ВСЕГДА заменяться на [ЛИЦО_1]** по всему документу. Для этого CLEARGATE поддерживает реестр сущностей на уровне сессии:

При обнаружении сущности текст нормализуется (через морфологический анализ pymorphy3 и встроенную нормализацию Natasha), проверяется реестр на наличие совпадений (включая нечёткий поиск по Левенштейну и правила русских имён: «Иванов И.И.» = «Иванов Иван Иванович» = «Иванова» в косвенном падеже), и если совпадение найдено — возвращается существующий плейсхолдер, иначе генерируется новый с инкрементальным счётчиком по типу.

Формат плейсхолдеров: `[ЛИЦО_1]`, `[ОРГАНИЗАЦИЯ_1]`, `[АДРЕС_1]`, `[СУММА_1]`, `[ДАТА_1]`. Квадратные скобки выбраны как формат, лучше всего распознаваемый LLM — они сохраняют плейсхолдеры в ответе. Перед анонимизированным текстом добавляется легенда:

```
В тексте используются следующие обозначения:
[ЛИЦО_1] — физическое лицо (истец)
[ОРГАНИЗАЦИЯ_1] — юридическое лицо (ответчик)
```

### Хранение маппинг-таблицы

Маппинг «анонимизированный токен ↔ реальные данные» — **самый чувствительный элемент системы**. Архитектура хранения:

Данные хранятся исключительно **в оперативной памяти** (in-memory) на протяжении сессии. Используется `mlock()`/`VirtualLock()` для предотвращения выгрузки в swap. Шифрование — **AES-256-GCM** с сессионным ключом, производным от мастер-ключа через HKDF. При закрытии сессии — немедленная очистка через `sodium_memzero`. Для многосессионных сценариев (пользователь закрыл приложение и вернулся) — опциональное шифрованное сохранение на диск с автоматическим удалением через настраиваемый таймаут (по умолчанию 24 часа).

### Обработка больших документов (chunking)

Для документов, превышающих контекстное окно локальной LLM (или для оптимизации NER), применяется **двухпроходная стратегия**:

**Первый проход** — NER по всем чанкам: документ разбивается на фрагменты по 512 токенов с перекрытием 10–20% на границах предложений. NER запускается на каждом чанке, все обнаруженные сущности собираются в глобальный реестр.

**Второй проход** — консистентная замена: с использованием глобального реестра сущностей все чанки анонимизируются с гарантией единообразия плейсхолдеров. При пересборке перекрывающиеся области дедуплицируются.

Для документов, помещающихся в 1M-контекст облачных LLM (Claude 4.6, GPT-5.4 и Gemini 3.1 Pro поддерживают до 1 млн токенов на апрель 2026), чанкинг на этапе отправки в LLM не требуется.

### Единый интерфейс CLEARGATE над тремя API

CLEARGATE реализует **паттерн адаптеров** — каждый провайдер имеет собственный адаптер, говорящий на нативном API (не через OpenAI-совместимые shim), чтобы сохранить доступ к extended thinking, prompt caching и tool features.

| Возможность | Claude | OpenAI | Gemini |
|-------------|--------|--------|--------|
| Параметр thinking | `thinking.type: "adaptive"` + `effort` | `reasoning.effort` | `thinking_level` |
| Уровни | low/medium/high/max | none-xhigh | low/medium/high |
| Стриминг | SSE `thinking_delta` + `text_delta` | SSE стандартный | SSE `stream=True` |
| Биллинг thinking | Выходные токены | Выходные токены | Выходные токены |

**Оценка стоимости перед отправкой**: для каждого провайдера используется нативный подсчёт токенов. CLEARGATE показывает пользователю приблизительную стоимость запроса до нажатия кнопки «Отправить»:

```
Примерная стоимость: ~$0.45 (Claude Sonnet 4.6)
Входные: ~12,500 tok → $0.04 | Выходные (est.): ~25,000 tok → $0.38 | Thinking (est.): ~5,000 tok → $0.08
```

По умолчанию CLEARGATE выбирает **самую мощную модель** каждого провайдера с **thinking: high**.

### Переключение тем и языков — обязательная функциональность

CLEARGATE поддерживает **две темы** и **два языка интерфейса**, переключение доступно из любого экрана без перезагрузки:

**Темы** (переключатель в header с анимированной иконкой sun/moon):
- **Светлая**: фон #FAFAFA, поверхности #FFFFFF, текст #171717, бордеры #E5E5E5
- **Тёмная**: фон #0A0A0A, поверхности #262626, текст #F5F5F5, бордеры #2E2E2E. Акценты осветлены: синий → #4A8BD4, бордовый → #C47A8E, золотой → #D4B068

**Языки** (переключатель RU/EN в header):
- **Русский** — основной язык для юристов московского и петербургского офисов
- **English** — для минского, дубайского и кипрского офисов, а также для работы с англоязычными клиентами

Выбор темы и языка сохраняется в локальном хранилище и применяется ко всем экранам. Никаких модальных «выберите при первом запуске» — есть дефолт (тёмная тема, русский язык для московской инсталляции), который пользователь меняет в два клика.

**Типографика**: основной шрифт — **Inter** (отличная поддержка кириллицы, variable font, используется Linear и GitHub). Моноширинный — **JetBrains Mono** (разработан в России, идеальная кириллица). Для предпросмотра документов — **PT Serif** (спроектирован ParaType специально для русской типографики).

**Эффекты**: сдержанный glassmorphism только для оверлеев (`backdrop-filter: blur(16px)`), spring-анимации для переходов панелей, skeleton-лоадеры с shimmer при обработке документов. Тени трёхуровневые: cards → popovers → modals.

### Цветовое кодирование типов сущностей

Система из **8 цветов**, каждый с вариантами для светлой и тёмной темы. Доступность: все комбинации превышают контраст WCAG AA 4.5:1, палитра безопасна для дальтонизма (избегает чистого красного vs зелёного).

|-------------|-------------|------------|-------|
| ФИО | #DBEAFE (голубой) | #1E3A5F | 👤 PER |
| Организации | #FEF3C7 (янтарный) | #4A3728 | 🏢 ORG |
| Суммы | #D1FAE5 (изумрудный) | #1A3A2A | 💰 MON |

### Ключевые экраны

**Экран 1: Welcome / Вход**
Минималистичный экран с логотипом CLEARGATE, названием фирмы, формой авторизации (SSO через Active Directory ЕПАМ или локальный логин/пароль). Переключатели языка (RU/EN) и темы в углу уже доступны.

**Экран 2: Dashboard**
Левая боковая панель: навигация (Новая сессия, История, Настройки). Центральная область: список последних сессий в карточном виде (название/описание документа, дата, статус, использованная LLM). Верхняя панель: поиск по истории, быстрые фильтры (по дате, по LLM, по статусу), переключатели темы и языка. Статистика использования: количество обработанных документов за период, общая стоимость запросов к LLM.

**Экран 3: Новая сессия**
Два варианта входа: **загрузка файла** (drag-and-drop зона для DOCX/PDF/TXT, поддержка множественной загрузки) или **прямой ввод текста** (textarea с подсветкой синтаксиса). Выбор языка документа (русский/английский/автоопределение — это отдельная настройка, не путать с языком интерфейса). Выбор режима: «Полный цикл» или «Только анонимизация». Кнопка «Анализировать» запускает pipeline.

**Экран 4: Split-screen анонимизации** — центральный экран приложения.

Левая панель: оригинальный текст. Все обнаруженные сущности подсвечены соответствующими цветами (ФИО голубым, организации янтарным, суммы изумрудным и т.д.). Каждая подсвеченная сущность — интерактивна.

Правая панель: анонимизированная версия. Вместо реальных данных — плейсхолдеры: `[ЛИЦО_1]`, `[ОРГАНИЗАЦИЯ_1]` и т.д. Плейсхолдеры окрашены в тот же цвет, что и оригинал слева.

**Синхронизированная прокрутка**: обе панели скроллятся одновременно, сохраняя выравнивание. Разделитель — перетаскиваемый (drag handle) для изменения пропорций.

**Интерактивные действия с сущностями**: клик по подсвеченной сущности открывает попавер с информацией (тип, confidence score, предложенная замена) и кнопками:
- ✅ **Принять** — подтвердить анонимизацию
- ❌ **Отклонить** — убрать из списка замен (сущность останется как есть)
- ✏️ **Редактировать** — изменить тип или плейсхолдер
- ➕ **Добавить** — выделить текст вручную и пометить как сущность

**Боковая панель «Entity Navigator»** (сворачиваемая): список всех обнаруженных сущностей, сгруппированных по типу. Клик по сущности — обе панели прокручиваются к ней. Пакетные операции: «Принять все [ФИО]», «Отклонить все [Даты]». Индикатор прогресса ревью: «Проверено: 47/63 сущностей».

**Клавиатурные шорткаты**: Tab/Shift+Tab — перемещение между сущностями, Enter — принять, Backspace — отклонить, E — редактировать, ⌘K — command palette (поиск сущностей, пакетные операции, быстрые команды).

**Экран 5: Панель настройки запроса к LLM**

Появляется после завершения ревью анонимизации. Содержит:
- Выбор провайдера: три кнопки-карточки — Claude / GPT / Gemini
- Выбор конкретной модели: дропдаун с моделями выбранного провайдера. По умолчанию — топовая (Opus 4.6 / GPT-5.4 / Gemini 3.1 Pro)
- Переключатель Thinking/Reasoning: on/off + уровень (low/medium/high/max)
- Поле промпта: textarea для инструкций к LLM. Предустановленные шаблоны: «Проанализировать договор», «Подготовить заключение», «Найти риски», «Ответить на вопрос клиента»
- **Оценка стоимости** в реальном времени: при изменении модели/провайдера пересчитывается
- Кнопка **«Отправить»** — с явным подтверждением: «Текст будет отправлен в облачный API. Убедитесь, что анонимизация корректна»

**Экран 6: Просмотр ответа LLM**

После получения ответа (стриминг — текст появляется в реальном времени) правая панель split-screen трансформируется: вместо анонимизированного текста появляется **ответ LLM с автоматической деанонимизацией**. Все плейсхолдеры заменены обратно на реальные данные. Места, где LLM внёс изменения, подсвечены **diff-подсветкой** (стиль Monaco DiffEditor): добавленный текст — зелёный фон, удалённый — красный фон (перечёркнутый).

Переключатель режима: «Деанонимизированный ответ» / «Сырой ответ (с плейсхолдерами)» / «Diff с оригиналом».

**Экран 7: Режим «Только анонимизация»**

После анонимизации пользователь может экспортировать анонимизированный файл (DOCX/PDF/TXT/буфер обмена). Маппинг-таблица сохраняется в зашифрованном виде в сессии. Позже пользователь может импортировать обработанный файл обратно — CLEARGATE применяет обратную замену по сохранённому маппингу.

**Экран 8: Настройки**

Язык интерфейса (RU/EN), тема (светлая/тёмная/авто), API-ключи LLM-провайдеров (ввод и валидация), кастомные правила анонимизации (regex-паттерны, словари имён, стоп-слова), настройки безопасности (таймаут сессии, автоудаление маппинга), о приложении.

## Д. Безопасность (тестовая конфигурация)

На текущем этапе CLEARGATE разрабатывается как **внутренний экспериментальный инструмент** в полностью on-premise контуре. Приоритет — технологическая корректность, архитектурная чистота и UX. Полноценное соответствие 152-ФЗ и другим регуляторным требованиям — это отдельная веха в roadmap, которая потребует дополнительных функций (RBAC, audit trail, compliance-отчётность, уведомления Роскомнадзора), но не влияет на архитектуру MVP.

### Базовые принципы безопасности, заложенные с самого начала

Даже на этапе тестирования архитектура построена так, чтобы никакие чувствительные данные не покидали контур:

**On-premise by design**: вся анонимизация выполняется локально. Ни оригинальный текст, ни маппинг-таблица никогда не отправляются в облако. В облачные LLM уходит **только** уже анонимизированный текст с плейсхолдерами.

**Шифрование маппинг-таблицы**: AES-256-GCM с сессионным ключом. Хранение — в оперативной памяти с `mlock()` для предотвращения выгрузки в swap. При закрытии сессии — немедленная очистка.

**Политика логирования**: логируются только timestamp, тип действия, ID документа, метаданные API-вызовов (модель, токены, стоимость). **Никогда не логируются**: оригинальный текст, содержимое маппинг-таблиц, ключи шифрования.

**TLS 1.3** для всех API-вызовов к облачным LLM.

### Что добавится на пути к compliance-версии

Когда CLEARGATE выйдет за рамки тестового использования, roadmap включает: полноценный RBAC с 8 ролями, append-only audit trail с hash-chain, compliance-отчётность под 152-ФЗ, опциональную интеграцию ГОСТ-криптографии (Кузнечик) для сценариев с требованиями ФСТЭК, документирование информированного согласия клиентов на использование AI-инструментов. Всё это — расширения поверх уже заложенной архитектуры, а не её переделка.

### Доступность API из России

Практический вопрос: все три LLM-провайдера — американские компании. Необходимо мониторить доступность API-эндпоинтов и иметь fallback-стратегию: переключение между провайдерами, а также подключение российских LLM (YandexGPT, GigaChat) как резервного варианта.

### Final: продакшн-развёртывание на серверах ЕПАМ

**Kubernetes-кластер**. Бэкенд и фронтенд — горизонтально масштабируемые поды без GPU. ML-pipeline и Ollama — выделенные GPU-ноды (2–4× RTX 6000 Ada / A100 80GB / H200). Shared Redis для кэширования сессий. PostgreSQL для аудита и истории. HA через репликацию, auto-failover, rolling updates без простоя.

Нагрузочные характеристики Final: 50–200+ параллельных пользователей, среднее время анонимизации документа на 10 страниц — менее секунды, поддержка пакетной обработки сотен документов в ночном режиме.

## Ж. Roadmap

### Alpha (2–4 недели, вайб-кодинг через Claude Code)

Запуск на RTX 4060. Базовый workflow: загрузка TXT/DOCX → трёхслойная анонимизация (regex + spaCy + Qwen 7B) → split-screen с ревью сущностей → отправка в **Claude Sonnet 4.6** → стриминг ответа → деанонимизация. Ручная проверка перед каждой отправкой. **Оба языка интерфейса (RU/EN) и обе темы (светлая/тёмная) уже в Alpha** — это маленькая фича, которую проще сделать сразу, чем добавлять потом.

### MVP (месяц 2–3)

Запуск на рабочей станции с RTX 3090. Интеграция всех трёх LLM-провайдеров с unified interface. Поддержка DOCX и PDF. Diff-подсветка ответов LLM. Режим «только анонимизация» с экспортом/импортом. Переход на **Qwen 2.5 32B** как локальную модель — качественный скачок в точности NER и reasoning. Расширенный набор предустановленных промпт-шаблонов для типовых юридических задач.

### v2.0 (месяц 4–6)

Интеграция с EPAMOS (привязка сессий к делам CRM, автоматическое подтягивание контекста по клиенту). Полноценный RBAC с multi-user. Audit trail. Кастомные словари анонимизации по делам. History и поиск по сессиям. Начало работы над compliance-фичами под 152-ФЗ.

### Final v3.0 (месяц 7–12)

Продакшн-развёртывание в дата-центре ЕПАМ (2–4× RTX 6000 Ada / A100 / H200). Fine-tuned NER-модель на юридическом корпусе ЕПАМ. Интеграция с VERITAS (транскрибированные совещания → автоматическая анонимизация → анализ LLM). Пакетная обработка документов. Интеграция российских LLM (YandexGPT, GigaChat) как fallback-провайдеров. Полноценный compliance под 152-ФЗ. API для программного доступа из других приложений экосистемы.

## Заключение: почему CLEARGATE меняет правила игры

Юридическая индустрия стоит перед парадоксом: LLM радикально повышают производительность юристов, но профессиональная этика запрещает отправлять клиентские данные в облако. **CLEARGATE разрешает этот парадокс** — не через компромисс, а через технологическое решение, которое делает передачу данных безопасной по конструкции.

Три фактора делают CLEARGATE уникальным для российского юридического рынка. Во-первых, **on-premise NER-pipeline, заточенный под русский язык и российские идентификаторы** — ни один западный SaaS-продукт не знает про ИНН, ОГРН и формат российского паспорта. Во-вторых, **трёхслойная архитектура** (regex + NER + LLM) обеспечивает надёжность обнаружения, недоступную любому одному методу — вероятность пропуска чувствительных данных стремится к нулю. В-третьих, **архитектура масштабируется от ноутбука до дата-центра** без переписывания кода: Alpha на RTX 4060 для разработки, MVP на RTX 3090 для тестирования одним пользователем, Final на кластере A100/H200 для всего штата ЕПАМ.

Для партнёров ЕПАМ CLEARGATE — это не расход, а **конкурентное преимущество**: возможность использовать самые мощные AI-модели мира для анализа контрактов, подготовки заключений и юридического ресёрча, оставаясь в полном контроле над клиентскими данными. Это инструмент, который превращает ограничение в силу.
