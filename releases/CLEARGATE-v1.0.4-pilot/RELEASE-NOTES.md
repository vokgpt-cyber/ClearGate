# CLEARGATE v1.0.4 Pilot Release Notes

## Что зафиксировано

Пилотная версия приложения: `v1.0.4`.

Baseline commit приложения: `38077abbb0d8b1536479094880971914d0a730af`.

Эта версия зафиксирована как стабильная точка для внутреннего тестирования:

- загрузка DOCX, PDF и нескольких файлов в одну сессию;
- объединение нескольких документов в один пакет в порядке загрузки;
- ручной запуск анонимизации после загрузки;
- сохранение результата в сессии без повторной анонимизации при возврате;
- скачивание анонимизированного DOCX;
- загрузка ответа LLM и деанонимизация;
- режим сравнения с оригиналом;
- улучшенная подсветка переносов текста в сравнении;
- админ-раздел с пользователями, обратной связью и аналитикой;
- удаление сессий с подтверждением;
- локальный GPU LLM/verifier доступен как "Глубокая проверка".

## Важные ограничения пилота

1. "Глубокая проверка" пока является вспомогательным QA-инструментом.
   Основное качество дает базовый анонимизатор. Пользователям не стоит
   ожидать, что Deep scan автоматически исправит все пропуски.

2. PDF поддержан для пилота, но PDF всегда сложнее DOCX:
   OCR, перенос строк, таблицы и восстановление структуры могут давать
   больше ошибок, чем исходные DOCX.

3. Сравнение с оригиналом старается показывать переносы текста как `из` и
   `сюда`, но это эвристика. Для сложных перестановок больших фрагментов
   результат надо проверять глазами.

4. TLS и домен зависят от IT-инфраструктуры. Для лабораторного запуска можно
   использовать self-signed сертификат, для тестовой группы лучше corp_ca или
   полноценный сертификат.

5. До подключения LDAP/AD пользователи управляются локально через админку или
   CLI `cleargate-admin` внутри backend-контейнера.

6. Начиная с pilot.2, Docker build не использует `python -m spacy download`,
   чтобы установка не зависела от `raw.githubusercontent.com`. Обязательная
   модель `ru_core_news_lg` ставится из direct wheel URL GitHub Releases и
   проверяется во время сборки. Если wheel недоступен из сети IT, его нужно
   зеркалировать во внутренний mirror и указать `SPACY_MODEL_WHEEL_URL`;
   запуск без spaCy-модели запрещен, чтобы не снижать качество.

7. Начиная с pilot.3, GPU inference images были закреплены для совместимости
   с BGE-M3 и серверным GPU. Начиная с pilot.8, активный LLM/verifier работает
   через `ollama`/`gemma4:26b`, а `ghcr.io/huggingface/text-embeddings-inference:89-1.9`
   остается для BGE-M3. `HF_ENDPOINT`
   валидируется как абсолютный URL, чтобы не получать ошибку TEI
   `relative URL without a base`.

8. Начиная с pilot.4, TLS symlink'и для `selfsigned` и `corp_ca` создаются
   относительными путями, чтобы nginx видел их внутри mount
   `/etc/cleargate-certs`.

9. Начиная с pilot.7, базовый анонимизатор стал более строгим к организациям:
   широкие GLiNER-labels `organization` и `location` не применяются
   автоматически; родовые описания вроде `Адвокатское бюро`, `Бюро`,
   `компания`, `банк`, `реквизиты` отсекаются; конкретные юридические лица и
   профессиональные фирмы с названием, например `АО «Норд-Хим»` и
   `Адвокатское бюро ЕПАМ`, продолжают анонимизироваться. Deep scan также
   получил более строгие инструкции и не должен добавлять спорные ORG.

10. Начиная с pilot.8, вторичный LLM/verifier переведен с Qwen/vLLM на
    Gemma4 через Ollama: по умолчанию `CLEARGATE_LLM_MODEL=gemma4:26b`.
    Основной анонимизатор не менялся: правила, spaCy, GLiNER и BGE-M3
    остаются теми же.

11. Начиная с pilot.11, PDF, экспортированные из Word в режиме Track Changes,
    очищаются от зачеркнутых удалений до анонимизации. Подчеркнутые вставки
    сохраняются. Это снижает ложные срабатывания на текст, который визуально
    удален в исходном PDF. Также добавлен фильтр для служебных склеек вроде
    `Сотрудника / Примеры`.

12. Начиная с pilot.12, базовый анонимизатор использует policy layer
    `auto/review/ignore`. Для ДМС/страховых памяток и внутренних положений он
    стал строже к родовым словам и публичным названиям: `Сотрудник`,
    `Адвокатское бюро`, `Alice AI`, support-телефоны и города поддержки больше
    не должны попадать в автоматическую анонимизацию сами по себе. При этом ФИО,
    номера полисов, даты и конкретные фирмы вроде `Адвокатское бюро ЕПАМ`
    остаются в автоматическом контуре. Deep Scan теперь является только QA-
    списком предложений и не меняет документ без явного выбора пользователя.

## Что особенно тестировать

- DOCX договоры: аренда, заем, агентский, NDA, акт сверки, приложения.
- PDF договоры после OCR: суммы, адреса, реквизиты, таблицы.
- PDF из Word Track Changes: зачеркнутые удаления не должны попадать в
  анонимизированный DOCX и не должны порождать лишние сущности.
- Мультизагрузка: договор + приложения в одну сессию.
- Ручное добавление и исключение сущностей.
- Deep scan: включить, посмотреть предложения, отключить.
- Deep scan после pilot.12: проверить, что предложения не применяются сами,
  пока пользователь не выбрал нужные пункты в списке.
- ORG-качество: `Адвокатское бюро`/`Бюро` не должны анонимизироваться сами по
  себе, а `Адвокатское бюро ЕПАМ` и юрлица с `ООО`/`АО`/`LLC` должны.
- ДМС/страховые памятки: ФИО и номер полиса должны скрываться, а публичные
  support-телефоны, города офисов и название приложения не должны шуметь.
- Загрузка ответа LLM и возврат к анонимизации.
- Деанонимизация и скачивание итогового DOCX.
- Удаление сессий и проверка, что документы этой сессии удалены.
