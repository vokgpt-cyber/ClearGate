# CLEARGATE: простая инструкция для тестовых пользователей

CLEARGATE помогает подготовить юридические документы для работы с LLM:
заменяет чувствительные данные на плейсхолдеры, а потом может вернуть реальные
значения обратно в итоговый документ.

## 1. Войти

1. Откройте ссылку, которую передал IT-отдел.
2. Введите логин и пароль.
3. Если пароль не подходит, обратитесь к администратору CLEARGATE.

## 2. Загрузить документ

1. Нажмите `Новый документ`.
2. Выберите один DOCX/PDF или несколько файлов.
3. Если договор состоит из нескольких файлов, загружайте их вместе или
   добавляйте в одну сессию в нужном порядке.
4. CLEARGATE объединит файлы в один документ в порядке загрузки.

## 3. Запустить анонимизацию

1. После загрузки проверьте оригинал слева.
2. Нажмите `Анонимизировать`.
3. Дождитесь завершения.
4. Справа появится анонимизированная версия.

## 4. Проверить результат

Проверьте, что скрыты:

- названия сторон договора;
- ФИО;
- ИНН, КПП, ОГРН, БИК, счета;
- адреса;
- номера договоров;
- существенные суммы;
- даты, если они чувствительные для вашего сценария.

Проверьте, что не скрыты лишние слова:

- названия разделов договора;
- обычные роли вроде "Арендодатель", "Поставщик", "Покупатель";
- проценты НДС, если они не являются предметом анонимизации;
- единицы измерения вроде "кв. м", "тонн", "руб/т".

## 5. Исправить вручную

Если CLEARGATE что-то пропустил:

1. Выделите нужный фрагмент в оригинале.
2. Выберите тип сущности.
3. Добавьте его в анонимизацию.

Если CLEARGATE скрыл лишнее:

1. Найдите плашку сущности внизу.
2. Отключите или удалите ошибочную сущность.
3. Проверьте правую часть документа.

## 6. Глубокая проверка

Кнопка `Глубокая проверка` запускает локальный LLM/verifier на сервере.

Важно: в пилотной версии это вспомогательный инструмент. Он может быть полезен
для поиска подозрительных пропусков, но пока не всегда точен. Если после
глубокой проверки появились спорные изменения, их можно отключить.

Рекомендуемый подход:

1. Сначала оцените обычную анонимизацию.
2. Используйте `Глубокая проверка`, только если качество вызывает сомнения.
3. Смотрите предложения внимательно.
4. Если результат стал хуже, отключите слой проверки.

## 7. Скачать анонимизированный DOCX

1. Нажмите `Скачать DOCX`.
2. Сохраните файл.
3. Именно этот анонимизированный файл можно использовать в облачной LLM.

## 8. Поработать с документом в LLM

Пример:

1. Откройте вашу LLM.
2. Загрузите анонимизированный DOCX.
3. Попросите выполнить нужную задачу: анализ, резюме, правки, сравнение,
   таблицу рисков, проект письма.
4. Скачайте результат из LLM в DOCX.

Не загружайте в облачную LLM оригинальный документ с реальными данными.

## 9. Загрузить ответ LLM обратно

1. Вернитесь в CLEARGATE.
2. Откройте ту же сессию.
3. Нажмите `Загрузить ответ LLM`.
4. Выберите DOCX, который вернула LLM.
5. CLEARGATE покажет документ с восстановленными данными.

Если в ответе LLM появились новые плейсхолдеры, CLEARGATE может попросить
указать, какое значение подставить.

## 10. Сравнить с оригиналом

1. Нажмите `Сравнить с оригиналом`.
2. Зеленым обычно показываются добавления.
3. Красным обычно показываются удаления.
4. Переносы текста могут быть отмечены как `из` и `сюда`.

Сравнение помогает понять, что LLM поменяла по смыслу и структуре.

## 11. Скачать итоговый документ

Если результат устраивает:

1. Нажмите `Скачать деанонимизированный`.
2. Откройте DOCX локально в Word.
3. Проверьте документ глазами.
4. Дальше работайте с ним как с обычным Word-документом.

## 12. Удалить сессию

Если документ больше не нужен:

1. В списке сессий выберите нужную сессию.
2. Нажмите удаление.
3. Подтвердите удаление.

Удаление сессии должно удалить связанные документы этой сессии.

## 13. Сообщить о проблеме

Если что-то сработало неправильно:

1. Нажмите кнопку `?`.
2. Выберите категорию: баг, вопрос, предложение.
3. Кратко опишите проблему.
4. Если можно, укажите:
   - тип документа;
   - DOCX или PDF;
   - что должно было быть скрыто;
   - что было скрыто лишним;
   - на каком шаге возникла проблема.

Не вставляйте в сообщение реальные персональные данные, если это не требуется
для разбора проблемы внутри защищенного контура.
